# Architecture

A map of how `wkg-command-centre` is put together so a new developer can navigate the codebase and reason about request flow without reading every file. Pair this with [`DATABASE.md`](./DATABASE.md) for data-model detail and [`AZURE-SELF-HOSTING.md`](./AZURE-SELF-HOSTING.md) for the infra story.

> Local dev setup lives in [`DEVELOPMENT.md`](./DEVELOPMENT.md). Don't duplicate it here.

## TL;DR

- **Single Next.js 16 App Router app.** No microservices, no separate API server. Server Actions are the default mutation surface; HTTP route handlers exist only for things that *need* to be HTTP (auth callbacks, ETL cron entry, Inngest webhook, file exports, account-side endpoints).
- **One database.** Postgres, accessed via Drizzle ORM. Schema is a single file (`src/db/schema.ts`); migrations are SQL files generated by `drizzle-kit` (51 forward migrations, `0000`–`0050`; prod at id 51 as of 2026-05-12 — `0050` adds PT + US to `regions`).
- **Driver is portable.** `src/db/index.ts` auto-selects between `@neondatabase/serverless` (when the URL is `*.neon.tech`) and `postgres-js` (everything else). Self-hosted Postgres "just works" today; see DATABASE.md for the few places that leak.
- **Auth is Better Auth.** Invite-only, credentials provider, 30-day sliding sessions, roles `admin`/`member`/`viewer` plus a `system` role used only by automation. RBAC is enforced inside server actions/layouts — there is no `middleware.ts`. **Phase 10 (in flight)** swaps `redactSensitiveFields` for CASL `permittedFieldsOf` and turns roles into DB-stored, admin-editable rule sets.
- **Async is Inngest.** Email send + retry, weekly POC underperformance alerts, daily Bank-of-England FX fetch all run as Inngest functions (`src/inngest/`). The `/api/inngest` webhook is the single registration surface.
- **No edge runtime.** Every route handler that runs server code declares `runtime = "nodejs"`. Nothing in the app depends on Vercel-only platform features other than a single cron schedule, which already supports a bearer-token fallback.

## Runtime model

### Server Actions are the default mutation surface

Mutations live next to the page that triggers them in `actions.ts`. They:

1. Call `await auth.api.getSession(...)` (via a thin wrapper in `lib/auth.ts`).
2. Gate with `requireRole("admin"|"member"|...)` from `lib/rbac.ts`.
3. Apply scoping (e.g. `scoping/scoped-active-locations.ts`) for non-admins.
4. Mutate via Drizzle.
5. Write an `audit_logs` row.
6. Return a typed result; the client component does optimistic UI as needed.

There is no global middleware — gating is per action and per layout. The `(app)/layout.tsx` does the session check and the role-or-redirect.

### Route handlers (HTTP)

Only six exist:

| Route | Why it must be HTTP |
|---|---|
| `/api/auth/[...all]` | Better Auth's catch-all — sign-in, forgot-password, change-password, etc. |
| `/api/account/password-changed` | Server-confirms a `changePassword` event so the confirmation email can be queued |
| `/api/etl/azure/run` | Triggered by Vercel cron header **or** `x-etl-token: $ETL_SHARED_SECRET`. Returns 200/207/401/409/503. |
| `/api/inngest` | Inngest webhook — function registration + step invocation (see `INNGEST_*` env keys) |
| `/api/export/excel` | Streams a generated xlsx — too large for Server Action JSON return |
| `/api/export/csv` | Same — streamed download |

The ETL route declares `export const runtime = "nodejs"` and sets `maxDuration = 300` (blob enumeration can be slow). The others rely on the App Router default — which is also the Node runtime in this codebase, since nothing opts into Edge. **Do not add `runtime = "edge"` anywhere**: the DB driver, Resend client, `@aws-sdk`, `@azure/storage-blob`, and `pg` all need Node.

### Auth model

- Better Auth with the `drizzleAdapter({ provider: "pg" })`. Tables: `user`, `session`, `account`, `verification` — all standard Better Auth shape.
- `disableSignUp: true` — invite-only is a **locked decision**. New users come in via the invite flow (which uses Better Auth's reset-password URL with `?invite=1`).
- Session: 30-day expiry, refreshed daily (sliding window).
- The `admin` plugin provides `defaultRole: "member"` and `adminRoles: ["admin"]`.
- A custom `userType` field (`internal` | `external`) lives on `user` and is surfaced on `session.user` so the portal can hard-gate external users out of internal routes. `input: false` keeps `userType` out of any signup payload — it's set at invite time only.
- A `system` role exists for ETL/automation and is **excluded** from `Role` union in `lib/rbac.ts` — it must never be granted to a real user.
- `nextCookies()` is the **last** plugin in the array — it has to wrap Server Action responses.

### RBAC roles

| Role | Effective surface |
|---|---|
| `admin` | Everything: settings, data import, user management, all analytics, all locations |
| `member` | App surface; analytics scoped by `user_scopes`; cannot manage users or import data |
| `viewer` | Read-only app surface; same scoping as member |
| `system` | ETL only — automation actor for sales imports. Never user-facing. |

`userType=external` overrides the role surface to portal-only views. Internal-only sensitive fields (commission, costs) are filtered server-side regardless of role when `userType=external`. **The portal is currently feature-paused (2026-04-25)** — external sessions land on `/portal/coming-soon`. The `userType` plumbing is still in place for revival; see `src/app/portal/layout.tsx`.

**Phase 10 (in flight, Plan 10-01..10-08):** This 3-role + scope text-column model becomes hybrid `roles` (admin/Ops-IT tier/Read-only tier/custom) + `role_permissions` (subject × action × fields × conditions × inverted) + `user_roles` link table. `user.role` text becomes `role_id` FK. CASL builds an `Ability` once per request in `src/lib/auth/get-user-ctx.ts`; `redactSensitiveFields` (currently inside `src/lib/rbac.ts`) becomes `permittedFieldsOf(ability, 'read', subject)`. Admin authors custom roles in `/settings/roles` (form-driven; no JSON editor in v1.1). Conflict resolution: explicit-deny-wins (AWS IAM semantics). `system` role bypasses CASL.

### Background work

| Job | How it runs today | Notes |
|---|---|---|
| Daily Azure sales ETL | Vercel cron `0 4 * * *` POSTs `/api/etl/azure/run` | `x-vercel-cron: 1` header **or** `x-etl-token` proves auth; gated by `ETL_AZURE_ENABLED=true`. Stamps `sales_records.net_amount_gbp` at ingest using BoE rate carry-forward (Phase 9.1); hard-fails the blob if rate is >7 days stale. |
| Daily BoE FX fetch (Inngest cron) | `fx-rates-fetch-daily` runs ~06:00 UTC, before the Azure ETL | Fetches Bank of England IADB CSV for ~25 majors, idempotent upsert keyed on `(currency, rate_date)`. Emits `fx_rate_fetch_failed` email to `FX_ALERT_TO` on error. (Phase 9.1) |
| Weekly POC underperformance alert (Inngest cron) | `weekly-poc-alerts` — Mondays 09:00 Europe/London | Classifies eligible Live kiosks against percentile cutoffs over `app_settings.underperformance_window_days` (default 30). Per-POC batched email; `payloadHash` keyed on `(poc_user_id, run_iso_week)` for idempotency. (Phase 9) |
| Email send + retry (Inngest) | `send-email` function — triggered by `email/send.requested` events from any caller that wrote to `email_log` | Send → Resend; retry logic inline (no separate retry function). `email_log.payloadHash` unique idx prevents digest dupes. (Phase 8) |
| Monday.com import | Operator-triggered in `/settings/data-import/monday`; structural reseed via CLI (`npm run db:reseed`) | Server action under `pg_try_advisory_lock` (key: import-specific constant). Hotel importer writes 15 metadata fields with fill-NULLs-only `ON CONFLICT DO UPDATE` (Heathrow: 8); SSM-Groups board auto-seeds `kiosk_config_groups` pre-Phase-1; pre-reseed `locations` snapshot to `/tmp/locations-pre-reseed-<ISO>.json` (PR #43, 2026-05-12). |
| Sales CSV import | Operator-triggered in `/settings/data-import/sales` | Stage → review → commit; staging table pruned 1d retention (#32) |
| Reset admin password | CLI: `scripts/reset-admin-password.ts` | Bypasses sign-up; documented in CLAUDE.md |
| (future) NetSuite ETL | TBD | `docs/smoke-checklist-netsuite-etl.md` exists as a smoke checklist; the runtime path is not yet wired |

All long-running work uses Postgres advisory locks (`pg_try_advisory_lock`) so two operators clicking the same button or two cron runs overlapping is a 409, not data corruption. Inngest crons get step-level idempotency from Inngest itself plus payload-hash idempotency at the `email_log` boundary.

## Request flow (cheat sheet)

```
Browser
  │  signed-in cookie (Better Auth session)
  ▼
Next.js (app router)
  │
  ├── (app)/layout.tsx ── auth.api.getSession() ── redirect /sign-in if missing
  │
  ├── Page (RSC) ── reads via Drizzle through `db` (auto-detected driver)
  │
  └── Form / button ── Server Action ── requireRole + scoping + audit + db
                         │
                         └── (rare) /api/auth/* via fetch — Better Auth handles
```

ETL flow:

```
Vercel cron / curl  ─POST→  /api/etl/azure/run
                              │  401 if neither x-vercel-cron nor x-etl-token
                              │  503 if ETL_AZURE_ENABLED!=true
                              ▼
                            runAzureEtl(db)
                              │  withAdvisoryLock(ETL_AZURE_LOCK_KEY) → 409 if held
                              │  for each region (with azureCode):
                              │    list blobs under {container}/{azureCode}/YYYY/MM/DD/*.csv
                              │    skip if already in sales_blob_ingestions (success)
                              │    AzureBlobSource.pull() → stage → commit
                              ▼
                            { processed[], skipped[], failed[] }  (200/207)
```

## Testing

- Unit + integration: `npm test` (vitest). Lots of `*.test.ts` colocated with code.
- E2E + UAT: `npm run test:e2e` (Playwright, headless). See [`tests/`](../tests) by domain (rbac, kiosks, sales, etc.).
- Remote/preview: `PLAYWRIGHT_BASE_URL=https://<preview> npx playwright test ...` runs against a live deployment instead of the local dev server. See CLAUDE.md for the Vercel git-branch alias rule.

## Things that are deliberately not in this codebase

- No microservices.
- No GraphQL server (we *consume* Monday.com's GraphQL but don't expose one).
- No global Redis / cache layer — Postgres is the cache.
- No CDN config in repo — relies on Vercel's CDN today; on Azure, Front Door / CDN is opt-in.
- No bespoke `email_jobs` queue table — Inngest is the queue; `email_log` is just the audit trail with a `payloadHash` unique idx for digest idempotency.
- No SSO / external IdP, no real-time collaboration, no mobile native app, no map view, no IoT/telemetry. See `.planning/PROJECT.md` § Out of Scope.
