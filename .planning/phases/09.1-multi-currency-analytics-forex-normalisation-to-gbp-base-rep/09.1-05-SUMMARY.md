## Decisions Made

- **Conversion direction is `net_amount / rate_to_gbp`, not `*`.** BoE quotes are foreign-per-GBP (1 GBP buys X foreign). 100 USD / 1.25 = 80 GBP (not 100 × 1.25 = 125). The plan body's `* rate` example was notational; the Wave 0 backfill RED test (`100 USD / 1.25 = 80 GBP`) is the authoritative spec. The pipeline test mirrors this and passes.
- **`getRateForDate` dbOverride parameter.** Production callers (pipeline.ts and azure-etl.ts) pass through the caller-provided db so transactions and Testcontainers contexts are honoured. Default falls back to `@/db` singleton for backward compatibility with existing/future callers.
- **azure-etl.ts pre-check queries `import_stagings.parsed_row` JSONB**, not `sales_records`. At the gate boundary the rows are still in staging — `_commitImportForActor` hasn't fired yet. JSONB shape is `{ parsed: { currency, transactionDate, ... }, resolution: {...} }`.
- **`inngest.send` (not `step.sendEvent`) for the azure-etl.ts fan-out.** The ETL is not an Inngest function — it's an HTTP-triggered server route. `step.sendEvent` is only available inside an Inngest handler. `inngest.send` is the equivalent at the HTTP/server-action layer (mirrors plan 09.1-04's distinction between `step.sendEvent` inside the handler and `inngest.send` outside).
- **Apply 0048 via psql, not drizzle-kit migrate.** Dev DB drizzle ledger is desynced (last recorded migration is idx 21, but 0046+0047 are clearly applied to the schema — they were applied manually outside drizzle-kit). Running `drizzle-kit migrate` would have tried to replay every migration since 0022 and failed. The 0048 SQL is idempotent (`DO $body$` with `is_nullable='YES'` guard) so direct psql apply is safe. This is a pre-existing dev DB state issue documented under "Issues Encountered" — fixing the ledger drift is out of scope for this plan.
- **Backfill test temporarily DROP NOT NULL on net_amount_gbp.** The backfill's contract is "rows that existed pre-0048 with `net_amount_gbp=NULL` → fill in". Recreating that pre-flip shape in a test means seeds must be allowed to leave the column NULL. Mirrors the production sequence: 0047 added the column nullable → backfill populated every row → 0048 flipped to NOT NULL.
- **Wave 0 backfill RED test relocation.** Original path matched the vitest unit project glob (`src/**/*.test.ts`) but the test uses Testcontainers (real Postgres) which is the integration project's shape. Plan 09.1-04 made the same fix for `fx-rates-fetch-daily`; plan 09.1-05 reuses the precedent.
