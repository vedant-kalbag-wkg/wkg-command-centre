## Decisions Made

- **WR-05 fix shape — `= ANY` over chunking:** Two viable approaches (chunk the NOT-IN list into 10k batches OR rewrite as `= ANY($::uuid[])`). Chose `= ANY` because (a) it's a single bind regardless of N, (b) drizzle convention already uses this shape elsewhere in the codebase (`trend-series.ts`, `queries/shared.ts`), (c) chunking introduces multiple round-trips and a coordination layer the simpler array form avoids.
- **WR-09 fix shape — comment + tests, code unchanged:** REVIEW.md WR-09's diagnosis confirms the asymmetric handling (FILTER on booking_fee, no FILTER on net_amount) is correct because the SUM populations differ. The code is right; the documentation needed to be load-bearing. Chose comment tightening + a marker-assertion test rather than refactoring the code (which would have risked breaking the very contract WR-09 identifies).
- **CR-05 SELECT projection kept `id::text AS id`:** The original cast served a JS interop purpose (forces pg to return uuid as a string for `SalesRow.id: string`). Removed it ONLY from the WHERE tuple and ORDER BY where it was breaking planner index use. The projection-side cast is wire-format only and does not affect plan or skip behaviour.
