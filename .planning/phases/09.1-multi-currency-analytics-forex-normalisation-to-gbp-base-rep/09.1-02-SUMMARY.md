## Issues Encountered

**1. `drizzle-kit push` interactive prompt + dev DB journal drift**

- **What happened:** The plan's Task 3 calls for `npx drizzle-kit push` against the dev DB. Two pre-existing dev-environment conditions surfaced:
  1. `drizzle-kit push` v0.31.10 requires a TTY for column-rename prompts and rejects non-TTY input. It heuristically asked whether `net_amount_gbp` is a rename of `net_amount` (false positive — the column added is genuinely additive, not a rename).
  2. The dev DB's `drizzle.__drizzle_migrations` table only has 21 applied entries while `migrations/meta/_journal.json` has 48 entries on disk (the local dev DB has been advanced manually past the journal cursor at some prior point — `sales_records` already exists). Running `scripts/migrate-neon-dev.ts` (the canonical project migrator) failed early on a guard from a much older migration ("Migration blocked: 19 active locations cannot be mapped to a region" — pre-existing test data state, not introduced by this plan).
- **How resolved:** Applied the two new migrations directly via `psql -f migrations/0046_*.sql` and `psql -f migrations/0047_*.sql`. Both files are idempotent (`CREATE TABLE IF NOT EXISTS` and `ADD COLUMN IF NOT EXISTS`) so this is the same outcome `drizzle-kit push` would have produced absent the false-positive rename prompt and the pre-existing journal drift.
- **Verification (matches the plan's `how-to-verify` block exactly):**
  - `\d exchange_rates` shows composite PK `(currency, rate_date)`, `rate_to_gbp numeric(18,10)`, `source text default 'boe'`, `fetched_at timestamptz default now()`
  - `\d sales_records | grep net_amount_gbp` shows `numeric(12,2)` allowing NULLs
  - `is_nullable = YES` confirmed via `information_schema.columns` — Pitfall 7 split honoured (0048 NOT NULL flip correctly NOT applied)
- **Out-of-scope:** The dev DB's journal/applied-migrations drift and the older "19 active locations" guard are pre-existing local-environment state from prior development work, not regressions caused by plan 09.1-02. Logged here for awareness; resolution belongs in a separate dev-environment cleanup, not this plan.
