## Decisions Made

- **Plain `db.select()` over `db.select({ rate: exchangeRates.rateToGbp })`.** The Wave 0 mock returns `SEED` rows verbatim (with `rateToGbp` field name) and ignores the projection. Reading `row.rateToGbp` on the SUT side works with both the mock and real drizzle (which returns columns under their schema property names when no projection is given). Cleaner than aliasing dance.
- **Empty CSV → `[]`, not throw.** Wave 0 test 5 (`"returns [] (or throws) for empty / blank CSV input"`) wraps the call in `expect(...).not.toThrow()` AND asserts `out === []`. Both must hold simultaneously, so the parser bails early on empty input.
- **Defensive post-fetch JS filter (`if (row.rateDate > isoDate) return null`)** even though SQL `lte` enforces it. Required because the Wave 0 mock's WHERE clause is a no-op (returns SEED verbatim). Cost in production: one string compare. Without it, `getRateForDate("USD", "2024-01-01")` would return the 2026-05-08 SEED row instead of `null`.
- **Series-code re-export from boe-fetch.ts.** Wave 0 test imports `{ parseBoeCsv, BOE_SERIES_TO_CCY }` from `./boe-fetch`. Re-exporting keeps the test's import surface unchanged while letting `currencies.ts` remain the canonical home.
- **27 series codes (one above the planned ~21).** `XUDLBK22…XUDLBK91` covers the BoE-published majors per D-03; combined with the 6 fixture-exercised entries the total lands at 27 mapped + GBP identity = 28 supported. Above the plan's "≥20" floor and below any meaningful coverage gap.
