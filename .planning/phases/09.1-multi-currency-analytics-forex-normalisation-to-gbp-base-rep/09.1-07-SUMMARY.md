## Decisions Made

All key decisions are documented in the frontmatter `key-decisions` block. Most consequential:

1. **Public types extended in-place rather than reshape to a dual-emit row.** Existing TS callers (`metrics.revenue` math) keep working unchanged; the new `revenueNative` + `currencyKey` are purely additive. Renderer call sites synth the snake_case `pickRevenueDisplay` row inline — the camelCase TS public shape is still ergonomic for non-renderer consumers (cache layer, server actions, page-level math).
2. **Pivot-engine grand-total dispatch is per-bucket, not per-row.** A multi-bucket pivot with bucket-A all-EUR and bucket-B all-GBP correctly renders bucket-A's grand total in € and bucket-B's in £; only when a bucket itself spans multiple currencies does the grand total fall back to GBP. This matches the SQL-side resolver shape (`CASE WHEN COUNT(DISTINCT currency)=1 ...`).
3. **Commission processor flips both cumulative base AND per-row engine call to GBP.** The plan called out the per-row decision as "audit"; the audit landed firmly on flipping — tier brackets are GBP-denominated, so the per-row contribution to the cumulative cursor must also be GBP. Mixing native per-row against a GBP cumulative cursor would mis-calculate boundary crossings. Defensive null fallback for pre-FX-backfill rows.
4. **Stale-rate banner threshold = 24h, not 7d.** 24h is the operator-facing early-warning bound; 7d is the downstream ETL hard-fail bound. The banner explicitly references both — the trigger that surfaced it AND the consequence the admin needs to prevent.

### Auto-added Critical Functionality

**2. [Rule 2 — Defensive null handling] commission processor null fallback for netAmountGbp**

- **Why:** `salesRecords.netAmountGbp` is nullable on the schema (rows ingested before the BoE fetch was wired carry NULL until backfilled). The plan's swap to `Number(rec.netAmountGbp)` would have produced `NaN` on a NULL row, which would then propagate through the engine and corrupt the ledger. Although the processor only runs on current-month fee rows post-FX-rollout (so NULL should not occur in practice), an explicit null-fallback is a correctness requirement.
- **What:** Added `rec.netAmountGbp !== null ? Number(rec.netAmountGbp) : Number(rec.netAmount)` — falls back to native if pre-FX-backfill rows leak through (defensive, not a happy path).
- **Files modified:** `src/lib/commission/processor.ts`

**3. [Rule 2 — Visual consistency] HotelGroupDetail.metrics.avgRevenuePerHotelNative**

- **Why:** Without a native sibling for the avg-per-hotel computation, the secondary "Avg Revenue / Hotel" tile would render in GBP while the primary "Revenue" tile rendered native (e.g. €) for a single-currency cohort. Visually jarring and a hidden source of operator confusion ("why is the average GBP but the total euros?").
- **What:** Added `avgRevenuePerHotelNative: number` to the metrics shape; `getHotelGroupDetail` computes it as `revenueNative / hotelCount`. The renderer dispatches both tiles on the same currency_key resolver so the symbol stays consistent across the row.
- **Files modified:** `src/lib/analytics/types.ts`, `src/lib/analytics/queries/hotel-groups.ts`, `src/app/(app)/analytics/hotel-groups/group-metrics.tsx`, `src/app/(app)/analytics/hotel-groups/page.tsx` (emptyDetail)
