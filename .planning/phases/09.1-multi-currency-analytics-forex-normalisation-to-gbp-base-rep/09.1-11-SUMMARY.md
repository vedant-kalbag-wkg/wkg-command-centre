## What Was Built

**Task 1 — NEW CR-01:** `getFxAlertRecipient()` was previously called inside catch blocks in both `fx-rates-fetch-daily.ts` and `azure-etl.ts`. If `FX_ALERT_TO` was unset, the throw from `getFxAlertRecipient()` would mask the original fetch error and lose its stack trace. Both call-sites now resolve `alertRecipient` once at function entry — before any try/catch. A misconfigured deploy fails immediately with "FX_ALERT_TO env var is required" rather than producing a misleading error from inside a catch block.

**Task 2 — NEW CR-02:** `EmailTemplate` was `"password-changed" | "poc-underperformance"` — missing `"plain-text"`. Both FX alert call-sites emitted `template: "plain-text"` but bypassed type-checking via loose `inngest.send` typing. Added `"plain-text"` to the union and created `tests/inngest/email-template-union.test.ts` as a compile-time regression guard (TypeScript assignability probe — if the union is narrowed, tsc rejects the assignment).

**Task 3 — C-1 + C-2 test regressions:**
- C-1 (`num-rooms-subquery.test.ts` line 126): regex `lgm\.location_group_id\s+IN\s*\(` was stale — drizzle's `inArray()` emits `"location_group_memberships"."location_group_id" in ($1, $2, ...)` (lowercase, quoted identifier). Updated to `/location_group_id"?\s*(in|IN|=\s*ANY)\s*\(/i`.
- C-2 (`fx-rates-fetch-daily.integration.test.ts`): after Task 1's CR-01 lift, `_handleFxRatesFetchDaily()` throws at run-start if `FX_ALERT_TO` is unset. Added `vi.stubEnv("FX_ALERT_TO", "ops@test.example")` to `beforeEach` and `vi.unstubAllEnvs()` to `afterAll`. Also added `vi.restoreAllMocks()` to `beforeEach` (required — without it, `vi.spyOn(globalThis, "fetch")` call counts bleed across tests). Added new test asserting the CR-01 contract: throws before fetch is called when env is empty.
