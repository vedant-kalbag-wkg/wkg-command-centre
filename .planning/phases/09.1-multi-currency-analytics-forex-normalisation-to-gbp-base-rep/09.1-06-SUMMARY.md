### Task 3 — Pivot-engine ALLOWED_COLUMNS dual-emit substrate (commit `3729b73`)

All 5 RESEARCH-inventory sites in `pivot-engine.ts` (lines 68, 69, 130, 349, 585) addressed:

- **Lines 68 + 69 (ALLOWED_COLUMNS net_amount + booking_fee):** field ids preserved verbatim. Saved pivots in production (which serialise `{field: "net_amount", aggregation: "sum"}` into JSON) keep resolving against the legacy alias `sum_net_amount` (D-17 / Pitfall 4 back-compat).
- **New parallel `CURRENCY_GBP_COLUMNS` map:** holds the GBP-normalised SQL fragment for each currency-typed field. Plus three pure helpers — `isCurrencyField`, `gbpAlias`, `currencyKeyAlias` — that make the dual-emit shape observable to consumers (renderer in 09.1-07).
- **buildPivotSQL auto-emit:** when a value config references a currency-typed field, the SQL builder transparently adds two extra columns to the SELECT — `<agg>_<field>_gbp` (same aggregation over the GBP companion) and `currency_key_<field>` (D-10 resolver). The booking_fee variant scopes the resolver to `FILTER (WHERE is_weknow_fee = true)` so the key tracks fee-only cohorts. COUNT aggregations skip dual-emit (currency-agnostic).
- **Line 130 (METRIC_COLUMNS Set):** unchanged — set membership is keyed on the legacy ids which are preserved.
- **Line 349 (formatCell):** annotated; the function continues to format the primary alias as GBP via formatCurrency. The native-vs-GBP dispatch (D-10) is intentionally **deferred to plan 09.1-07** because that plan owns the renderer-side migration of consumers (tooltips + cell renderers).
- **Line 585 (DIMENSION_LABELS):** annotated — variant (b)/(c) per the plan. The label map is identity-on-id; preserving the field id in ALLOWED_COLUMNS keeps the label resolution working unchanged. The renderer-side label tweak (e.g., "Revenue (native)" / "Revenue (GBP)") is plan 09.1-07's call once the dispatch is live.

7 new pivot-engine tests cover: ALLOWED_COLUMNS back-compat, CURRENCY_GBP_COLUMNS shape, helper purity, end-to-end SQL emits the 3-column substrate, COUNT skips dual-emit, booking_fee FILTER predicate carries through, and a saved-pivot row keyed on `sum_net_amount` still resolves to a non-empty cell.

## Decisions Made

All key decisions are documented in the frontmatter `key-decisions` block. Most consequential:
1. **Public revenue field binds to GBP arm internally.** Avoids forcing every consumer (UI metric tiles, cached query callers, server actions) to migrate in a single plan. Renderer dispatch (D-10 cell-flip) is the final consumer migration and lives in plan 09.1-07.
2. **Pivot-engine field id `net_amount` preserved verbatim.** Saved pivots are user-controlled JSON in `app_settings`; renaming the id silently breaks them on first reload. The companion GBP arm + currency_key are added via parallel allowlists, not by mutating ALLOWED_COLUMNS.
3. **outlet-types tier classifier ORDER BY switched to GBP** (Pitfall 6 / D-12). Single-mode site (uses `buildSalesTxnCondition` not `buildAmountModeCondition`) but still cross-currency — the operator's tier-review backlog should surface by absolute £-impact, not raw native magnitude.

- **Found during:** Task 2 (initial type check after the maturity-analysis + trend-series swaps)
- **Issue:** Comments inside `sql\`...\`` template literals contained backticks (e.g., `` `avgRevenue` ``), which terminate the JS template literal and cause cascading TS1005 syntax errors.
- **Fix:** Removed backticks from inline comments in maturity-analysis.ts (line 122) and trend-series.ts (lines 206, 238). Future-proofed the comment style by switching to bare identifier names (e.g., "avgRevenue and totalRevenue").
- **Files modified:** `src/lib/analytics/queries/maturity-analysis.ts`, `src/lib/analytics/queries/trend-series.ts`
- **Verification:** `npx tsc --noEmit -p tsconfig.json` clean across the analytics surface after the fix.

**2. [Rule 1 — Bug] Test fixtures using legacy `revenue:` driver-shape keys**

- **Found during:** Task 2 (post-swap test run revealed 9 fixture failures producing `NaN` from `Number(row.revenue_gbp)` when fixtures emitted only `revenue: "..."`).
- **Issue:** Pre-existing test fixtures in `heat-map.test.ts`, `hotel-groups.test.ts`, and `portfolio.test.ts` mocked `db.execute` with the OLD column name (`revenue`). The query consumers were updated to read `revenue_gbp` per the dual-emit contract, so the fixtures had to be migrated too — strictly part of the plan's surface, not an out-of-scope test repair.
- **Fix:** Each fixture was rewritten to emit the dual-emit driver shape — `revenue_native: "...", revenue_gbp: "...", currency_key: "GBP"`. The test fixtures use GBP for both arms in single-currency-default test cases (the FX path itself is exercised in Task 4's new cohort assertions). 9 failing tests went green.
- **Files modified:** `src/lib/analytics/queries/heat-map.test.ts`, `hotel-groups.test.ts`, `portfolio.test.ts`
