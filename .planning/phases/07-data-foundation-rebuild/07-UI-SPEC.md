## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip padding, inline badge gaps |
| sm | 8px | Compact element spacing, conflict chip gap |
| md | 16px | Default element spacing, dialog body padding |
| lg | 24px | Section padding, toolbar horizontal padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: Table row touch target minimum 44px height (already applied as `min-h-[44px]` in location-table.tsx). BulkToolbar: `py-3 px-6` fixed bottom strip.

## Typography

Two weights only (WeKnow brand allows Light 300, Book 400, Medium 500, Bold 700 — 600 semibold is NOT a Circular Pro weight):

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (Book) | 1.5 | Default prose and table cells |
| Label | 12px | 400 (Book) | 1.4 | Secondary labels, captions |
| Heading | 20px | 700 (Bold) | 1.2 | Section headings, dialog titles |
| Display | 28px | 700 (Bold) | 1.2 | Page-level display text |

Bold (-10 kerning, per WeKnow brand guidelines): apply `tracking-[-0.01em]` to all `font-bold` elements. Do NOT use `font-semibold` (weight 600) anywhere — use `font-bold` (weight 700) for emphasis.

Source: `globals.css` `@theme inline` block, WeKnow brand guidelines.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (`--background`) | Page backgrounds, dialog surfaces |
| Secondary (30%) | `#F4F4F4` (`--color-wk-light-grey` / `--muted`) | Cards, sidebar, table header, dialog footer (`bg-muted/50`) |
| Accent (10%) | `#00A6D3` (`--color-wk-azure` / `--primary`) | See reserved list below |
| Warning | `#F4BA1E` (`--color-wk-gold`) | Same-name banner only |
| Destructive | `#F41E56` (`--color-wk-destructive`) | Destructive actions only (archive confirmation, undo locked state) |

Accent (`#00A6D3`) reserved for:
- Selected canonical record ring in MergeDialog (`border-primary bg-primary/10`)
- Selected conflict chip in MergeDialog (`border-primary bg-primary/10 text-primary`)
- Selected table row background (`bg-primary/20`)
- Table row hover (`bg-primary/10`)
- Primary CTA buttons (`bg-primary text-primary-foreground`)
- Merge button in BulkToolbar

Tint rule: minimum tint is 10% (`bg-primary/10`). Do NOT use `bg-primary/5` — below WeKnow brand minimum.

Warning (`#F4BA1E`) reserved for:
- Same-name guardrail Alert banner on `/locations` page (D-08)
- Same-name status row on `/admin/health` page (D-08)

Destructive (`#F41E56`) reserved for:
- Archive confirmation dialog button (existing)
- Undo merge button on audit log entry detail (admin-only, D-04)
- Undo locked state: greyed `text-muted-foreground` with reason tooltip (D-05)

Source: `globals.css`, WeKnow brand guidelines, `bulk-toolbar.tsx`.

## Surfaces and Interaction Contracts

### Surface 1: /locations page — Same-name guardrail banner (new)

**Primary visual anchor:** The warning Alert banner above the table. It is the first element in the viewport on this page when duplicates exist; the table below is supporting context.

**Trigger:** One or more same-name location groups exist in the DB (detected server-side).

**Markup:** Add a `warning` variant Alert component above the LocationTable. Inject via RSC before the table wrapper div.

**Alert variant to add (alert.tsx):** `warning` — background `bg-[#F4BA1E]/10`, border `border-[#F4BA1E]/40`, icon `AlertTriangle` from lucide in `text-[#F4BA1E]`.

**Copy (pre-populated from D-08 + DATA-03):**
- Heading: "Duplicate location names detected"
- Body: "{N} location group{s} share the same name. Select affected rows and use Merge to consolidate them."
- CTA inline link: "View duplicates" — scrolls to / pre-filters table to same-name rows.

**Dismissal:** None — banner persists while duplicates exist. Clears on server re-render once all groups resolved.

---

### Surface 2: MergeDialog — N→1 merge (extend existing)

Existing component: `src/components/table/merge-dialog.tsx`. Extend; do not recreate.

**Current behaviour:** Two-step flow — (1) pick canonical record, (2) resolve field conflicts — then single "Merge {entity}s" CTA.

**Phase 7 additions (D-01, D-03):**

**Step 2.5 — Consequences preview (new, insert before DialogFooter):**

Primary visual anchor for step 2.5: the consequences-preview block is the focal point — destination canonical record name displayed at top of the block, followed by the changes list, with the footer CTA as secondary. The `bg-muted/30` container establishes this as a distinct summary zone.

- Section heading (Label): "What will happen"
- Bulleted list (ul, `space-y-1 text-sm text-muted-foreground`):
  - "{sourceIds.length} location{s} will be archived"
  - "All kiosk assignments re-pointed to {targetName}"
  - "All sales records re-attributed to {targetName}"
  - "A snapshot of original data will be saved to audit log"
- Visual affordance: light `bg-muted/30 rounded-lg p-3` container for the bullet list.

**Snapshot note (D-03):** No UI change required; snapshot is DB-layer. Surface in the consequences preview text above.

**Sentinel triage path (D-07):** When the page context is `/locations/<sentinel-id>` (i.e. entityLabel = "orphan kiosk"), MergeDialog renders in reassign mode:
- DialogTitle: "Reassign {N} orphan kiosks"
- DialogDescription: "Pick the real location to move these kiosks to. Their sales records will follow."
- "Keep this record" label changes to: "Assign to this location"
- Footer CTA label: "Reassign kiosks"

### Surface 3: BulkToolbar — Merge button (existing, no change)

Existing: `src/components/table/bulk-toolbar.tsx`. Merge button renders when `onMerge` prop provided and `selectedCount >= 2`.

**No visual change required.** The button already matches the contract: `Merge` icon + "Merge" label, `border-primary` hover, height 8 (32px).

**Label note:** The BulkToolbar renders "Merge" (single word) as a space-constrained abbreviated label in the fixed bottom strip. This is intentional — the full primary CTA label "Merge locations" appears only in the MergeDialog footer CTA. Do not expand the toolbar label.

**Minimum selection guard (D-01):** Already enforced by `selectedCount >= 2` condition. For sentinel triage, this guard is relaxed to `selectedCount >= 1` (reassigning a single orphan is valid). Pass `mergeMinCount={1}` prop — BulkToolbar needs this prop added.

### Surface 4: Audit log entry detail — Undo merge button (new surface)

**Route:** `/settings/audit-log/[id]` — new page, admin-gated.

**Layout:** Full-width detail panel. Pattern mirrors existing admin pages: `PageHeader` + scrollable content area.

**Undo merge section (D-04, D-05):**

Rendered only when `audit_log.event_type === "location_merge"`.

**Active state (undo available):**
```
<section className="border rounded-xl p-4 space-y-3">
  <h3 className="text-sm font-bold tracking-[-0.01em]">Undo this merge</h3>
  <p className="text-sm text-muted-foreground">
    Restores {N} archived locations and reassigns {K} kiosks to their original locations.
    Sales records will be re-attributed. This action is logged.
  </p>
  <Button variant="destructive" size="sm">Undo merge</Button>
</section>
```

Undo confirmation: inline confirmation pattern (not a separate dialog) — button first click shows "Are you sure? This cannot be further undone." with "Confirm undo" (destructive) + "Cancel" (outline) replacing the original button. Transition via `useState`.

**Locked state (D-05):** Button replaced with:
```
<p className="text-sm text-muted-foreground flex items-center gap-2">
  <Lock className="size-3.5 shrink-0" />
  Undo locked: {reason}
</p>
```
Where `reason` is one of:
- "One or more kiosk assignments were modified after this merge."
- "Locked by administrator."

### Surface 5: /admin/health page (new surface)

**Route:** `/admin/health` — admin-gated, new RSC.

**Layout:** `PageHeader` ("System Health") + card grid (2-column on md+).

**Primary visual anchor:** Status pills on each card are the primary visual anchor. They communicate actionability at a glance; card body text and CTAs are supporting context.

**Same-name status card (D-08):**
- Card title: "Duplicate location names"
- Status pill: `bg-[#F4BA1E]/10 text-[#8A6B0E] rounded-full px-2 py-0.5 text-xs font-bold tracking-[-0.01em]` — "Action required" when duplicates exist, `bg-[#68D871]/10 text-[#2E7D32]` — "Clean" when none.
- Body: "{N} group{s} with same name" or "No duplicate names detected."
- CTA: "Resolve in Locations" → links to `/locations?filter=same-name`.

**LOCATION_NEEDED status card:**
- Card title: "Unmatched kiosks"
- Status pill: same pattern, "Action required" / "Clean".
- Body: "{N} kiosk{s} awaiting location assignment" or "All kiosks assigned."
- CTA: "Review orphans" → links to `/locations/<sentinel-id>`.

**Card shell:** `border rounded-xl p-4 space-y-3 bg-card` — matches existing card pattern.
