## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Drizzle-kit push interactive prompt | `drizzle-kit push` on this repo prompts for column-rename / truncate guesses on a TTY. CI / automation runs blow up with "Cannot read properties of undefined" or "Interactive prompts require a TTY". | blocking | Use `drizzle-kit generate` (non-interactive) OR raw `ALTER TABLE … ADD COLUMN IF NOT EXISTS` / `CREATE … IF NOT EXISTS` via `pg.Pool` for schema deltas. Phase 7 took the second path; migration `0039_phase_07_normalised_name_and_merge_snapshots.sql` is hand-authored to be `IF NOT EXISTS`-idempotent so prod cutover via `drizzle-kit migrate` works regardless of starting state. |
| Single transaction across runbook = Neon storage cap | Wrapping wipe + Monday import + commission tier import + all sales CSVs in ONE transaction blew past Neon's 512MB project storage cap during Plan B's first end-to-end run. | blocking | Two-phase tx in `scripts/v2-wipe-and-reseed.ts`: PHASE 1 atomic (wipe + sentinel + hotel-import + assets-import + commission-tier + audit log); PHASE 2 per-CSV transactions (each idempotent via sourceHash dedup, recoverable mid-failure). PHASE 3 spawns the backfill script outside any tx. |
| `drizzle(pool)` checks out a different connection than the runbook's PoolClient | The hotel/assets/commission importers couldn't see the uncommitted wipe state when drizzle was bound to the Pool — they'd race against `client.query("BEGIN")` because each drizzle query acquires a fresh pool connection. | blocking | Pin drizzle to the SAME `PoolClient` that holds BEGIN/TRUNCATE: `drizzle(client) as unknown as any` (the unknown cast is needed because the prod app type is `postgres-js` and the runbook is `node-postgres`; the call surfaces are structurally compatible). Snapshot in `scripts/v2-wipe-and-reseed.ts:218`. |
| Wiping `markets` cascades to `regions` via `regions.market_id → markets.id` | Plan B's first `WIPE_TABLES` list included `markets`; `TRUNCATE markets CASCADE` dragged regions down with it (cascading FK is from regions to markets, the other direction). The runbook then SELECTed regions and got back only the GLOBAL row it had just inserted — every hotel hit "skipped-no-region". | blocking | Preserve `markets` in the wipe set (already done in `scripts/v2-wipe-and-reseed.ts:WIPE_TABLES`). Markets had 0 rows in the Plan A snapshot anyway. |
| Postgres self-FK violation on chunked sales inserts | `_commitImportForActor` chunks inserts at 1000 rows; `sales_records.original_record_id → sales_records.id` is IMMEDIATE (not DEFERRABLE), so a reversal in chunk N referencing an original in chunk N+1 fires a FK violation when chunk N is committed. | blocking | Sort `prepared` so non-reversals (originals) flush before reversals: see `src/app/(app)/settings/data-import/sales/pipeline.ts:_commitImportForActor` ordering pass. Don't undo it. |
| Monday GraphQL retry only handled rate-limit errors | Long Phase 7 runs hit transient HTTP 502/503/504 from Monday's gateway. The default retry predicate only matched "rate limit"/"complexity"/"budget exhausted". | advisory | Broadened `isRateLimitError` in `src/lib/monday/client.ts` to also retry on `http 502/503/504`, `gateway timeout`, `bad gateway`, `service unavailable`. Don't narrow it. |
| GitIgnore did NOT cover `seed_data/` initially | Plan B's first commit accidentally added 87MB GB sales CSVs. | advisory | `.gitignore` now lists `seed_data/` and `.env.uat`. Operator-supplied seed CSVs and per-branch UAT credentials must NEVER land in git. |
