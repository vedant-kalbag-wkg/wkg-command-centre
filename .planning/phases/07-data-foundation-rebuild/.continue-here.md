## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Drizzle-kit push interactive prompt | `drizzle-kit push` on this repo prompts for column-rename / truncate guesses on a TTY. CI / automation runs blow up with "Cannot read properties of undefined" or "Interactive prompts require a TTY". | blocking | Use `drizzle-kit generate` (non-interactive) OR raw `ALTER TABLE … ADD COLUMN IF NOT EXISTS` / `CREATE … IF NOT EXISTS` via `pg.Pool` for schema deltas. Phase 7 ships hand-authored migrations `0039` (Phase 7 schema deltas) and `0040` (drop locations.outlet_code, add monday_item_id, partial unique on customer_code) — both `IF NOT EXISTS`-idempotent so prod cutover via `drizzle-kit migrate` works regardless of starting state. |
| Single transaction across runbook = Neon storage cap | Wrapping wipe + Monday import + commission tier import + all sales CSVs in ONE transaction blew past Neon's 512MB project storage cap. | blocking | Two-phase tx in `scripts/v2-wipe-and-reseed.ts`: PHASE 1 atomic (wipe + sentinel + hotel-import + assets-import + heathrow-import + canonical fee fallbacks + commission-tier + audit log); PHASE 2 per-CSV transactions (each idempotent via sourceHash dedup, recoverable mid-failure). PHASE 3 spawns the backfill script outside any tx. |
| Single client held across Phase 1+Phase 2 = Neon idle-kill | Holding a single PoolClient for the full ~6-min Phase 1 (Monday GraphQL fan-out) and into Phase 2's chunked 95k-row INSERT triggered Neon's serverless idle/duration kill mid-commit ("Connection terminated unexpectedly"). | blocking | After Phase 1 COMMIT, release the client and check out a fresh PoolClient for Phase 2. Re-acquire the advisory lock on the new session. Snapshot in `scripts/v2-wipe-and-reseed.ts` at the Phase-1→Phase-2 swap block (commit `f3984df`). |
| Empty `product_code_fallbacks` rejects 50% of sales rows | Without canonical fee mappings (Booking Fee→9991, Cash Handling Fee→9992) seeded into `product_code_fallbacks`, the upstream NetSuite export's empty-Code rows for WKG-collected fees fail validation at staging — 47661 of 95103 rows rejected. | blocking | STEP 5b inside Phase 1's atomic tx INSERTs the canonical mappings (`scripts/v2-wipe-and-reseed.ts`, commit `f3984df`). Mappings sourced from `src/lib/csv/sales-csv.ts:180-183` and `src/lib/commission/processor.ts:109`. Don't drop them. |
| `drizzle(pool)` checks out a different connection than the runbook's PoolClient | The hotel/assets/commission importers can't see uncommitted Phase 1 state when drizzle is bound to the Pool — each drizzle query acquires a fresh pool connection. | blocking | Pin drizzle to the SAME `PoolClient` that holds BEGIN/TRUNCATE: `drizzle(client) as unknown as any`. After Phase 1 COMMIT, rebind drizzle to the new client (see connection-swap pattern). |
| Wiping `markets` cascades to `regions` via `regions.market_id → markets.id` | Plan B's first `WIPE_TABLES` list included `markets`; `TRUNCATE markets CASCADE` dragged regions down with it. | blocking | Preserve `markets` in the wipe set. |
| Postgres self-FK violation on chunked sales inserts | `_commitImportForActor` chunks inserts at 1000 rows; `sales_records.original_record_id → sales_records.id` is IMMEDIATE (not DEFERRABLE), so a reversal in chunk N referencing an original in chunk N+1 fires a FK violation. | blocking | Sort `prepared` so non-reversals (originals) flush before reversals: see `_commitImportForActor` ordering pass. Don't undo it. |
| Alphabetical seed-CSV ordering picks wrong corpus | `seed_data/*.csv` sorted alphabetically with `--max-csv 1` picks the first alphabetic match (Feb before Jan), not the prod-canonical Jan 2026 corpus. | advisory | Use `WKG_NETSUITE_VK.csv` (renamed to `seed_data/GB_WKG_NetSuite_Jan2026.csv`) — the EXACT file used to seed prod (95103 lines = 95103 + 1 header, exact match to GOLDEN_SALES_RECORDS). The other Feb/Mar CSVs are stashed at `seed_data/_stash_full_corpus/`. |
| Mirror columns are NOT independent sources of truth | `mirror9` and `mirror3__1` on hotel boards both mirror data from the Assets board (`outlet_code1` and `text9` respectively). Falling back to mirror values when Assets is empty does nothing — they reflect Assets exactly. | advisory | Don't propose mirror9/mirror3__1 fallback as a way to "recover" missing data. The 50-kiosk operator gap is genuinely missing Monday data on Assets, not just on hotel boards. |
| `locations.outlet_code` conflated kiosk + hotel identity | The v1 schema mounted outlet_code (per-SSM identifier used in bookings) on `locations` (per-hotel concept) as the unique key. The proper key is customer_code (RPS account = hotel account). | blocking | Plan 07-06 dropped `locations.outlet_code` (preserving old values in `locations.notes` per operator request) and added `locations.customer_code` + `locations.monday_item_id` as the canonical identifiers. Sentinel re-keyed to (name='LOCATION_NEEDED', region=GLOBAL). 30 outlet_code call sites refactored. |
| Ready to Launch + Heathrow `In Progress` placeholders need NULL customer_code | These pre-deployment hotels have no Monday Assets entry, no kiosks, no real customer_code yet. | advisory | Importer inserts them with `customer_code = NULL`, `monday_item_id = item.id`, `notes` flagging pre-deployment status. Partial unique on (region, customer_code) is WHERE customer_code IS NOT NULL so multiple-NULL placeholders coexist. |
| GitIgnore did NOT cover `seed_data/` initially | Plan B's first commit accidentally added 87MB GB sales CSVs. | advisory | `.gitignore` lists `seed_data/` and `.env.uat`. Operator-supplied seed CSVs and per-branch UAT credentials must NEVER land in git. |
