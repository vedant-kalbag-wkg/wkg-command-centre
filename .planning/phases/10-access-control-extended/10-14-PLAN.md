## Cluster A — root cause confirmed

`src/app/(app)/locations/actions.ts:283-289` does CASL field redaction:

```ts
const ctx = await getUserCtx();
const allowed = new Set(readableFields(ctx.ability, "Location"));
const redacted = Object.fromEntries(
  Object.entries(locationData).map(([k, v]) => [k, allowed.has(k) ? v : null]),
) as LocationWithRelations;
```

`readableFields(ctx.ability, "Location")` returns the **Drizzle column names** of the `locations` table (see `src/lib/casl/fields.ts` + `fieldsOfSubject` + `getTableColumns`).

But `LocationWithRelations` carries three derived (non-column) fields populated from JOINS or denormalisation:

- `hotelGroupMemberships: Array<{ id: string; name: string }>` — populated from `location_hotel_group_memberships` join (actions.ts:238-254, 276).
- `assignedKiosks: Array<{ assignmentId, kioskId, ... }>` — populated from `kiosk_assignments` join (actions.ts:257-271, 277).
- `internalPocName: string | null` — populated from `user` join (actions.ts:226-234, 275).

None of these keys appear in `getTableColumns(locations)`, so `allowed.has(k)` is `false` for ALL three regardless of which role is signed in. They get nulled out in the redaction pass.

Downstream consumer `src/components/locations/location-detail-form.tsx`:
- Line 373: `location.hotelGroupMemberships.map((m) => m.id)` → TypeError when null
- Line 385: `setSelectedHotelGroupIds(location.hotelGroupMemberships.map((m) => m.id))` → same
- Line 389: `new Set(location.hotelGroupMemberships.map((m) => m.id))` → same
- Line 940: `<LocationKiosksTab assignments={location.assignedKiosks} />` → not a .map at component boundary, but consumer further down likely renders `assignments.map(...)`.

This explains the run-to-run flake on can-component.spec.ts:57 (viewer-no-merge): some location ids resolve through code paths that exercise the .map earlier than others (e.g. depending on which conditional branch the form renders first on different DOM order). Both admin and viewer hit the same null.map; viewer just happens to render the form fully on some pages because the early hotelGroup membership branch can short-circuit.

The clean fix is at the RSC boundary (`src/app/(app)/locations/[id]/page.tsx`) — backfill the missing keys to safe defaults BEFORE passing `location` to `<LocationDetailForm>`. This is preferable to:
- Editing `getLocation` to whitelist derived fields (changes the server-action contract; risk to other call sites)
- Editing the redaction loop to skip non-column keys (changes the CASL field-redaction semantics; out-of-scope)
- Editing every `.map` site in location-detail-form.tsx (5+ sites, fragile)
